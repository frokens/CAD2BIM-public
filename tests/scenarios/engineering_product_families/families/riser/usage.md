# RISER Family candidate

Self geometry requires two standard `external_constraints`, keyed `bottom` and `top`, each with a `fixed_point` condition containing `point_m`, a nonzero `axis`, and `outer_diameter_m`. Fixed points provide world bottom B and top T; their displacement gives the unit direction `v` and actual axial height `H=|T-B|`. Equal positive endpoint diameters give D. Coincident endpoints, unequal diameters, or axes inconsistent with the actual end signs are rejected; this Family does not add elbows or transitions. Public product parameters contain only section evidence. `product_origin O` remains separate. Source projection retains the original base, exact source top, approved height, direction and OD provenance, verifies them, and submits their standard target projection without duplicating installation fields in public parameters. `section.known_wall_thickness_m=[]` retains unknown wall evidence.

The condition axis is the external datum's outward axis. With the default `direction_relation: opposed`, bottom uses `+v` and top uses `-v`. Explicit `same` supplies product outward axes `-v` and `+v`. Both interfaces require fixed targets and circular OD checking, allow `same` and `opposed`, and cap position/angular tolerances at `1e-6`. The Backend still independently checks the independently evaluated Geometry interfaces.

The Program computes world `Pbottom=B` and `Ptop=B+Hv`. Bottom and top outward axes are `−v` and `+v`. It projects world Z onto the plane perpendicular to `v` for frame X; close to Z it uses world X. `frame_y=v×frame_x`, so `(frame_x,frame_y,v)` is orthonormal and right handed. At the bottom, the outward-axis frame uses the same X and the opposite Y. The solved Geometry parameters use bottom `[0,0,0]`, top `[0,0,H]`, axis `+Z` and reference `+X`; the existing fragment placement contains the original frame and bottom offset. One `IfcPipeSegment` component owns one `riser_body` fragment. Its Geometry evaluator independently returns `bottom`/`top` external interfaces from these parameters, with outward extrusion axes and outer circular profile D. The shape-only build retains the actual terminal-face checks; independent BREP inspection compares the declared frames with actual face centers and normals.

`realize(ctx)` puts `B−O` in the fragment translation and `(frame_x,frame_y,v)` in its rotation columns. Geometry receives the local body from zero to `[0,0,H]`; the Backend applies the existing fragment and product placement chain once, restoring both original world endpoint frames. `standard_model(ctx)` constructs the existing nominal 3 m vertical riser with OD `0.25 m`, creates its two fixed targets internally, and uses the shared solver. It reads only section and no caller installation targets. The Backend places the nominal body at the unchanged O. For identical product input, any two O values yield the same nominal local geometry and local interfaces.

For `realize`, endpoint-difference arithmetic or world-to-local subtraction that cannot preserve H returns `AMBIGUOUS/numeric_capacity`; it is not described as a geometrically impossible riser. Coincident supplied endpoint positions are an invalid zero-height input. The independent nominal entry uses its finite local targets and cannot be rejected by unrelated source-coordinate offsets. The numeric Program does not call CADQuery. A numeric `SOLVED` still requires actual Geometry, body, end-face and interface checks. No old sample height or OD bounds are carried forward. There is no automatic elbow, host inference, pipe matching, hydraulic passage claim, or registration in this candidate. R1–R3 in `preview_cases.json` are authoring examples; formal execution and same-scene connection checks follow later review.
