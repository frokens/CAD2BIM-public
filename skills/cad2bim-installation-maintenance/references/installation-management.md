# 安装管理

## 根据目标和依赖组织工作

确认需要交付的对象、原始设计、既有设施与允许调整范围。复用准确已发布 Family、现有输入和当前模型；根据依赖决定哪些关系先确定、哪些结果需要写后再协调。可以在生成输入时统筹，也可以维护已有安装，不将某一产品类别或固定阶段顺序写成通用要求。资源自身布局由 Family 求解；跨对象关系由安装任务管理。

原始 Package 保持不可变。保留给定行与业务值是为了保存来源，不禁止有依据地派生合法的新输入。派生内容应说明来源、变更原因及一对多关系，不能为使工具通过而偷偷改小目标集合。必要时沿已有 Data 资料追查更原始来源；不默认重新分类全部 CAD，也不把仅含产品键的摘要当作已有 CAD 实体关联。

## 从可行域到当前安装关系

输入条件限定可行域；Geometry 的局部数值接口经 Family 变换，给出求解选定的位置、轴和 profile。后台对 Family 已声明内部关系及本行 external_constraints 独立求值，frame_check_status 表达其 PASS／FAIL。完成求值、条件通过、实际构造及模型提交各自表达不同事实；构造及提交仅更新请求范围内产品。

例如，finite_segment 从 [0,0,0] 到 [2,0,0] 米，允许求解器选择 [0.4,0,0] 米处的接口；2 米窗口并非设备占用量，相邻管道当前终点也未因此改变。安装任务依据关联和当前保存状态比较接入点、方向、截面与保留路径，再决定派生输入或编辑已有对象；不同差异需要各自依据。

命名接口是数值参照，实际 Body 端面是材料边界，真实 IfcPort／连接关系是网络拓扑。原报告保持该次快照，后续 placement／replace 不更新其接口坐标；维护后从当前对象取得位姿与所需事实再复核。按任务要求确定实体接合和间隙的检查深度，符号表示的未验证范围另列。

## 建立能够用于维护的对象关联

优先沿准确输入键、来源列、绑定、原 Operation、products／components GUID 和接口键追查，再结合坐标系、位置、方向、截面、路径与允许范围验证关系。对象能被 GUID 寻址，与它已被证明属于某一安装关系，是两件事。原条件没有宿主 GUID 时可继续调查；不能仅因此宣布无法维护，也不能把最近点、同名键或相近坐标直接当作归属。

保留有依据的候选和关联理由。发生多候选、方向不一致、同一路径多个占用或来源不足时，将歧义限定到实际受影响对象组。几何邻接、设计关系和真实网络连接分别记录；没有网络端口时仍可判断有证据的几何关系，但不得伪造拓扑。

## 把调查结果接到可执行计划

可用现有 Data Package 保存下面这些信息，不要求建立另一套固定 Schema。源关系已提供时，先以原产品／接口键接本次 Apply 的 products／components GUID，再核当前事实；近邻搜索只补没有来源的候选。

| 信息 | 可复用的记录示例 | 消费方式 |
|---|---|---|
| 来源与允许域 | 原 Package／行键、源产品和对端接口、原路径／段／顶点、原窗口及派生子窗口、方向、单位、pending 及理由 | 识别谁与谁有关；保留来源与窗口分配依据 |
| 本次求解与当前观察 | Operation／revision、根／组件 GUID、求解接口值、当前 Body 端点与轴各自记录 | 核对同一关系在本次保存状态下的事实，不把窗口当成已选裁口 |
| 完整路径计划 | 原路径、相关设备组、保留／退出区间与依据、动作、目标及父源→子段 | 生成 Edit 或必要新增输入，检查内部占用与区间覆盖 |
| 覆盖与未决 | 未检查、候选、关联歧义、已证无需改、已维护、站位冲突、构造失败、例外接收依据 | 决定下一项工作并如实交付；候选不计为已证，例外不改变关系检查结果 |

例如，一台设备两口分别接到两条原管，另一个设备位于其中一条管的路径内部。端点近邻可以漏掉内部设备；只修改第一台设备的一口，也可能改变另一侧的可留范围。以原完整路径和共享设备组组织这些证据，保存动作后只补读受影响的接口、管体和邻侧关系，复用未改变部分。允许的表示应按任务与准确 Family 合同选择，外观偏好不能自动提升为更严格的安装验收条件。

## 协调局部修改与耦合冲突

首次安装规划与已有模型维护都要沿已有来源关系，同时考虑管道两端、路径内部设施及共享设备另一侧，确定可用路径和必须保留的部分。结合已求解接口、已有保存体及尚未写入的计划判断占用，不只分别配对近邻端点，也不固定先设备后管或先添后改的顺序。

`finite_segment` 是接口可选域，不是必须全部占用的长度。为关联管段保留构造空间时，可在原允许域内派生非零子窗口，使用现有输入表达，并保留原窗到子窗的依据。子窗口须包含于原域且不倒转方向，遵守原外径条件、参数与资源合同及任务功能要求；不能靠越域或暗改参数凑解。优先选择可行且较少挤占相邻管段的候选，不无条件压缩设备、追求全局最小或套用固定比例、安全距离。

单产品的选解偏好可能吃满允许窗口，本产品 SOLVED 不保证为关联管段留下余量。出现零／负余长或选口落到必须保留段的边界时，先依据准确 Family 使用说明和实际诊断，必要时才查源码，区分硬构造下界与选解偏好，再按实际自由度协调相关侧。先用数值与必要条件筛选，只对有依据的候选做必要实体验证，避免反复构造已知不适配的方案。

窄窗不保证求解器单调缩小设备占用，需复核实际选定接口、构造结果及所有关联侧；正的中心线余长也不保证 `miter_room`、短段构造或实体衔接通过。来源、原允许域和派生选择、报告接口与当前 Body 分别留证，依赖改变后只补核受影响部分。

同时核对实际构造或表示是否改变。默认／符号表示即使 SOLVED，也不能充当任务要求的详细构造完成；任务明确接受该表示时按其实际范围交付，不一概要求 detailed。

区分已证独立的工作与仍耦合的冲突。可以按业务依据组织独立批次，工具每批的严格原子性仍保持；已确认原子拒绝或回滚的批次为零提交，超时、断联或终态不明时先查原 Operation。后续批次须能说明如何覆盖所有尚未完成目标，不能只留下容易成功的子集。原允许域内且已获授权的关联设备协调直接继续，并复核所有受影响侧。只有超出已授权安装选择、改变不可调整的设计条件或引入新的设计决定时，才保留现场并提出相应裁决选项。

## 管理保留、拆分、退出与失败

维护动作根据实际依据选择 replace、placement、delete 或新增残段，详见[产品编辑](product-edit.md)。删除需要业务正当性；删掉受冲突管道不会自动解决设备冲突。拆分要保留原段、各保留区间和新增对象之间的来源关系，直到所需对象全部保存并核查。结果数量不能单独证明对象之间的来源关系。

使用其它构件、折线路径等替代表示时，说明保留和改变的接口、形体、类别、源身份与业务功能。几何能够构造不等于业务等价，是否接受以任务要求和已有授权为准。

始终以用户交付范围内的原始目标集合做分母，逐源追查当前保留、合法变更／拆分／退出、失败和未决。一个源可以对应多个保存对象；范围内未变化对象仍属于交付范围。范围外对端或未选入本次建模的来源关系可记录为边界，不自动扩大目标，也不能假称已安装。处置记录只说明状态，范围内未闭合关系不能记为安装通过；行数守恒、非空 GUID 或“已处置”标签不能单独证明完整性。退出区间应有设计与安装依据，不能把未保留的差集自动称为设备实际消耗。

## 设计受限与交付例外

未找到合适方案时，说明已知冲突、原允许自由度、实际尝试及失败范围，区分当前选解不可用、搜索／证据不足和有依据的设计受限。设计受限应有具体依据，例如固定设备尺寸与不可移动设施、必须保留的路径或功能要求在原允许空间内确实冲突。一次窗口选择失败或零余长不证明整个允许域无解；无需穷举全域或另建优化平台，也不能把没尝试或不确定写成不可能。

任务明确接收设计例外时，可保留原对象并完成带设计例外的过程交付；例外仍逐项留在任务范围内的完整分母和未闭合关系中，该关系的安装结果不因此 PASS。若任务要求范围内全部连接，则目标仍未达成，Skill 不能自行改变验收标准。

沿现有 Data Package 的关系、计划或未决记录表达例外的原来源、关联对象、允许窗口、实际证据及后续设计变更需求，不增加固定 Schema 或状态平台。确需改变设计、资源支持域或路线时，按实际授权提出具体选项；不能靠删冲突行、删管或声称自动拓扑闭合消除问题。

尚不能完成或证据不足时，保留业务缺口：范围内受影响的原对象与未闭合关系仍在完整分母，保留已有有效结果、当前模型及其 Operation／Package 引用和原失败，不静默跳行、删管或把部分维护说成完整交付。继续已获授权且独立的工作；面向用户的最终说明按[业务缺口汇报](results-and-recovery.md#最终交付与业务缺口)组织。

## 核查实际保存结果

复用后台已经完成的参数、求解、接口与构造验证，针对变化范围检查实际 GUID、产品子树、世界位姿、路径／截面、必要实体适配及跨对象关系；不能只查 Placement／Body 非空就称位姿或安装已核对。replace 后子件身份可能更新，拆分新增与删除都要反映到当前来源映射。

检查受影响的对端、共享依赖和需要保护的未变对象；已有证据未受影响时可复用。必要的代表性形体检查应说明范围与限制，不默认逐件网格、整图碰撞或每次重复全模型查询。只有实际检查过的事实才能给结论；历史报告、作者自报与保存体读回分别说明。结果组织及中断恢复见[结果与恢复](results-and-recovery.md)。
