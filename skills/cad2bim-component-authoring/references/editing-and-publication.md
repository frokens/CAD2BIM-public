# 局部修订与正式发布

## 局部修改

继续编辑草稿时使用准确 draft_ref 和当前 edit_token；省略的字段按合同继承，显式 null 不是省略。冲突先读取当前对象，再基于实际内容修改。结果未知时先找回原 Operation，不创建新的重复写入。

已有发布资源需要修改时，从明确的准确版本建立可编辑草稿，继承未变元数据；不默取 latest，也不修改不可变发布版本。草稿阶段持续更新同一草稿，发布后形成新的业务版本。需要正式使用修改后的内容时再发布；旧正式版本不会因为新草稿存在而被覆盖。

在原字段内表达修改，不另造 change 字段：源码使用现有有界成员修改；usage_instructions 可完整 set 或对准确原文 edit；Geometry 参数 Schema、Family 定义集合按当前工具支持的条目 set/remove 修改。未改的说明、绑定和合同无需重新抄写。字段操作细节按需读取当前资料，复杂整体变化可以完整 set。

同次修改涉及源码、参数、绑定和标准定义时同步保持一致。整体合并通过预检才保存；不能把部分失败当作已经保存。保留工具要求的准确并发和成员修改条件，不额外添加无消费者的 SHA 或人工合同版本。

## 使用说明随业务变化维护

以实际 Schema、准确依赖以及可用源码／资产信息为依据编写说明，不能只凭名字或图片。说明按产品实际需要组织，不强制固定标题模板；Geometry 说明局部形体、参数作用与接口，Family 说明组成与条件化装配，各自保留所属职责。

输入意义、支持域、构造、求解或失败边界变化时，检查继承来的说明并仅修改受影响内容；继承不代表后台会根据源码自动重写。允许的替代表示应写清触发条件和判断限制。说明面向使用者，不写实验编号、交接记录或开发历程，不重抄参数表和算法。

外部管道或装配条件只在该资源确有职责时说明；放置模型并不自动检查或修改外部对象，不把几何接口称为已持久化 IFC 端口或管道连接，也不宣称尚不可用的安装操作可调用。字段长度、文本匹配和继承等精确规则仍读取当前 R。

## 发布职责

草稿可直接 Preview，成功保存模型可直接 Query 和观察，不要求先 Publish。需要正式可发现、可选择的资源版本时使用当前 Publish；发布不等同于业务或外观验收。

Publish 按资源自身定义生成正式资产。固定 Geometry 构建正式固定体，参数化 Geometry 发布程序与参数合同；Family 固定所需准确绑定，具备标准模型能力时按其标准定义生成标准模型。Preview 示例可作来源导航，不是发布取模型的来源，也不是一组 PASS 资格门禁。

有正式 Family 标准资产时，通过当前 family_standard_model 观察／Query 入口直接读取已保存资产，不重新求解。没有该能力时不伪造标准模型。

发布失败或回执未知用原 Operation 找回真实终态，不暴露或使用半发布资源。真实发布版本、准确引用、草稿 CAS 和 Scope 保留。任务不要求发布时，交付可继续使用的草稿及保存模型引用即可。
