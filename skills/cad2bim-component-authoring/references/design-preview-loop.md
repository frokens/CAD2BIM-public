# 设计与 Preview 形成闭环

每次 Preview 应回答一个明确问题，而不是为了得到更多 PASS。先提出当前设计判断，选择能辨别它的输入，再看实际结果，最后决定是否需要修订。

## 一次有效迭代

1. **先定义问题。** 例如“出口转向时固定设备是否仍保持尺寸，连接点是否仍在两个许可窗口内”，而不是笼统地“验证一下”。
2. **找到责任层。** 站位和布局属于 Family；实际形状、孔道与端面属于 Geometry；字段包装属于调用输入；出图或保存异常属于对应执行阶段。
3. **选择一个有区分力的代表。** 使用主要分支或相邻边界，不同时无目的改变十个参数。合法输入先固定；预期拒绝要写具体业务原因。
4. **保存一次实际结果。** 若预计需要换视角、截面或 Query，保留模型。后续检查沿同一个 inspection，避免每次观察都重新求解。
5. **按问题选择观察。** 整体比例看整体；接合看接口及局部；内部材料看必要截面／量测。输出已经回答的问题不重复检查。
6. **据结果作最小修订。** 保留原失败，针对已证实原因修改所属实现；说明哪些案例受影响。工具合同没有问题时，不为作者用法错误要求改后台。
7. **重验受影响代表并结束。** 未变化的输入和来源身份保持稳定，复用成功结果。没有新缺口时不继续增加相似场景。

## 常见现象与下一步

| 现象 | 先看什么 | 有依据后怎样调整 |
|---|---|---|
| 模型明显过长，但端口检查通过 | Family 分配给直段的长度、弯曲退距及目标紧凑性；接口检查不判断设计美感 | 调整合法布局选择与实际构造占用，不改源管端点 |
| 端口位置或方向不对 | 坐标系、管轴与外法线、局部到世界变换、接口来源 | 修所属位姿／接口计算；用原输入和一个整体变换例核对 |
| 输入校验拒绝 | 第一处字段路径、分支和原请求 | 按当前 Schema 修正确字段，不兼容猜写旧格式 |
| Preview 成功但局部形体异常 | 本次保存体、局部视图、必要实际端面或截面 | 修 Geometry 构造；不能只改接口声明 |
| 渲染失败或显示诊断警告 | 构建与保存是否成功，受影响对象和诊断阶段 | 复用保存体定位；不靠重复出图判断已经恢复 |
| 执行预算停止 | 触发维度、计数与阶段，实际复杂度 | 减少不必要工作或报告限制；不直接把技术失败当无解 |
| Family 找不到安装位置 | 支持域、有限窗口、主体刚性和搜索范围 | 区分硬冲突与搜索不足，不暗改输入 |

## 结束条件不是固定调用数

所需代表已覆盖、必要接口与形体要求有实际结果、图片清楚且引用可继续使用、失败和限制已说明，就结束本轮。发布不是这条检查链的自动终点；用户需要正式版本时才另行发布。

规范检查、业务核收和演示展示应按责任分工，避免作者与主控对同一未变资产重复做相同审计。若用户只要求外观与基本通孔，不能借闭环增加未约定的精细制造检查。
